## 2. Notable findings (structural / high-value)

**Message / command dispatch tables**
- **`FUN_1000a896` `[CONFIRMED @0x1000a896]` — command-id dispatch table.** A `switch` over ~30 command ids (`0x22ff054c`, `0x22ff058f`, `0x2ff04fe`, `0x3004b6d`, `0x23004b76`, `0xc2ff0563`, `0xe3166801`, …) that `operator_new`s the matching handler and calls `handler->vt[0](param_2,param_3)`. Every occupant handler is CLSID **`0x207edc0e`** subtype **`0x57e`** (matching `SIMGEOM.md`'s Tiles.ini occupant), differentiated by an instance id (`0xd1`–`0xf8`, `0x1f41`, `0x1f94`, `0x234b`–`0x234e`, `0x3e8a`, `0x1f5d`–`0x1f60`, `0x1f8b`–`0x1f8e`, `0x1f98`–`0x1f9b`). Four ids use a **4-way rotation** (`FUN_10016169(&DAT_10030968) & 3`) to pick one of 4 consecutive instance variants.
- **`FUN_10019e15` `[CONFIRMED @0x10019e15]` — typed property visitor / dispatch.** Reads a tag from `param_1 vt+0xc`; tags `0x8000`–`0x800f` copy 16 getter→setter slot pairs (source `vt+0xc4..+0x138` → this `vt+0xc4..+0x134`); tags `0`–`0xc` read primitives; `0x7fff` and `0` are special cases. This is the property-marshalling core.

**Save/load serialization pair `[CONFIRMED]`**
- **`FUN_1001e516` = LOAD**, **`FUN_1001e226` = SAVE** — exact mirror image over the same field set and the same two flag bytes. The occupant record has optional sections gated by **`*(this+0x0a)` bits `0x20/0x40/0x80`** and **`*(this+0x0b)` bits `1/2/4/8/0x10`**, scalar fields at `+0x04/+0x08/+0x0c/+0x18/+0x1c/+0x20/+0x24/+0x38/+0x3c`, and four collections at `+0x40/+0x4c/+0x58/+0x64` (the last an array of 8-byte records). `FUN_10002cc2` is the versioned entry that drives the load with a shape code (1/2/3) and calls `FUN_1001e516`. Stream read vtable: `+0x38` u32, `+0x34` blob, `+0x60` object; write vtable: `+0x88` u32, `+0x84` blob, `+0xb0` object.

**Grid data structure `[CONFIRMED]`** (from `FUN_1000f0b0` / `FUN_1000ed50`)
- `this+0x90` = lock object (`vt+4` lock, `vt+8` unlock), `this+0x98` = cell-value 2D array (data ptr at `+0xc`), `this+0x9c` = cell-flag 2D array (data ptr at `+0xc`), `this+0xa0` = width, `this+0xa4` = height. **Flag byte bit0 = occupied, bit1 = multi-tile cell** — the cell value is then a packed anchor coordinate (`lo16 = x`, `hi16 = y`) that dereferences to the origin cell, so a footprint is counted once at its anchor.

**Redraw / notify message id `[CONFIRMED]`**
- **`0x637c0dab`** is posted by both `FUN_1001392a` and `FUN_1001364f` via `FUN_10018460()->vt+0x10(msg, 0)` after a region scan, carrying a packed bounding box (`(x0>>8)<<16 | y0>>8`, `(x1>>8)<<16 | y1>>8`). This is the building-layer dirty-rect / repaint notification.

**Placement path `[CONFIRMED]`**
- `FUN_10006df6` (multi-tile place, uses footprint service `0xc14f8955` and QI `0xe0faadc7`) → `FUN_100072f6` (feasibility: terrain-slope check via grid `vt+0x4c/+0x50` min/max height, tile-type `vt+0x58==4`, per-tile cost `this+0x30 vt+0x58(7)`) → `FUN_10007760` (commit occupants across layers) → `FUN_10008599` (per-building sound/effect id). `FUN_10021f61` is the interactive placement-cursor/preview updater.

**Resource-key groups discovered**

- **`0x82e0074c`** — query/info-panel label strings (`FUN_10024603` instances `0xc4`–`0xc7`,`199`,`0x30`; `FUN_10024a04` instances `0x31`,`0x32`).
- Query-text formatting is a family: `FUN_100202a7`, `FUN_1001ffdd` (per-`%variable%` resolver), `FUN_10024603`, `FUN_10024a04`, all emitting through `FUN_10020f0f`.

**Occupant footprint accessors `[CONFIRMED]`**: `this vt+0xd4` and `vt+0xd8` return the occupant width/height (masked `& 0xff`), multiplied for area in `FUN_10024a04` and `FUN_1001408d` (`this+0x60 * w * h`).
