## 2. Notable findings

**Per-tick scheduler / update entry point — `0x100278b0` (highest value).** This is a `Simulate`-style tick. It reads the game clock (`param_1+8` vt `+0x1e4`), floors the year to `0x76c` (1900) `[CONFIRMED @0x10027905]`, and pulls **three tunables keyed 3000 / 5000 / 8000** out of the map at `param_1+0xc` into `param_1+0x18/+0x20/+0x1c` `[CONFIRMED @0x100278d3-0x10027925]`. It then walks a record ring buffer (`param_1+0xb4 .. +0xb8`, stride `0x1c`), computing `slot = clock - 0x5911 + minor*0xc` and firing per-record callbacks (`record+4` vt `+0x64`) against a `ushort` count array (`record+0x10..+0x14`, stride 8). It dispatches to `FUN_10028dab / FUN_1002891b / FUN_10028eb2` and posts through the graph service (vt `+0x1d8` then `+0x28`). Subsystem tag `sim-events` is `[UNCERTAIN]` — the date arithmetic and ring buffer are date-scheduled event dispatch, but no string anchor names it.

**Serializer / deserializer pairs (save-load) — the dominant pattern in this slice.** Stream reader vtable convention: `+0x38`=read int32, `+0x18`/`+0x40`=read byte, `+0x28`/`+0x48`=read other. Writer convention: `+0x88`=write int32, `+0x68`=write byte, `+0x78`/`+0x90`/`+0x98`=write other. Confirmed pairs:
- **Ordinance state** — `0x10019c53` (load) / `0x10019d5a` (save). Load writes into the 40-byte ordinance record at `+0x04` (enable) and `+0x05` (leaf), **exactly matching the record layout already in `SIMMISC.md`** — this cross-confirms that map. GZCLSID pair `0x41193c3a`/`0xe1193c2a`.
- **Aura record** — `0x10002784` (load) / `0x100028f1` (save), keyed on GZCLSID `0xc259c02d` (the S12 aura class from the module map), iid `0x199627`. Fields `+0x90`(byte, clamped <16), `+0x94`, `+0x98`, `+0x80`, `+0x7c`, `+0x84`.
- **Deal/graph-view record** — `0x10036f36` (load, computes a `×1000` rate) / `0x10037058` (save); constructed by `0x100218d2`.
- **Placed-object record** — `0x10036277` (save, emits a GZCOM id triple via query `0x80199683`) / `0x100360de` (load).
- Plus `0x100194bf` (load, 2 strings + 8 ints), `0x10033e90` (save of three fixed arrays sized **12 / 10 / 10** dwords), `0x10036802` (record-reader ctor with a **`0xDEADBEEF` sentinel** at `this+8`), and `0x1002cc3b` (text `getline`, 40-byte chunked, CR/LF split).

**UI command-dispatch handlers (message-id switch tables).** `0x10020cc9` handles command ids `0x32`–`0x36` (50–54) plus an indexed range `>=0x64` into a list at `this+0x5c` (stride `0x28`), posting notifications `0x724a82e1` / `0x724a82de` (subtype `0x628d0c45`, codes `0xbbc`=3004 / `0xbbe`=3006) / `0x724a82dd`. `0x1001e836` handles ids `0x20`–`0x23` (help via `0x15`, two mutually-exclusive layer toggles gated by `DAT_10049f1c`, and posts `0x724a82da`). These are the panel button/menu handlers.

**Window/view factory usage.** `0x1001bc3d` (main window, id `0x42dd813a`, 500×480, position persisted in `DAT_10049f20`/`f24`/`f1d`), `0x10021a06` (child view id `0x82e00e34`), `0x1001ea54` (child view id `0x42dddc93`). All via the view factory GZCLSID `0xa2a79fd0`/iid `0xa2a79fd1`.

**Layer init/shutdown pair with message registration.** `0x10007a59` (init) registers for messages `0x62e8630b`, `0x23b4418f`, `0x6569de54` and posts `0x229a8a90`; `0x10007bb9` (shutdown) unregisters the same three and frees a **3-entry record array** at `+0x84` (stride `0x88`). The 3×`0x88` records and the `+0x80`/`+0x84`/`+0x88` offsets are shared with the label builder `0x10008439` (three currency readouts, `val*1000-100000`).

**Aura radius-stamp — `0x1001370c` (and its two byte-identical twins `0x10012040`, `0x10013e71`).** Reads a radius from `this+8` (vt `+0xd4`/`+0xd8`), fetches the world layer (`FUN_10032100` vt `+0x11c`, width `+0xcc`, height `+0xd0`), and stamps the value `param_1` into every object of a matching type (`this+4` vt `+0x18`) within a `2×radius` box, via iid `0xe0faadc7` setter vt `+0x48`. Three identical emissions in the binary — noted, not merged.
