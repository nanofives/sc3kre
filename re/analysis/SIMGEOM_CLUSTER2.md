## 2. Notable findings (structural / high-value)

### Save-file section GROUPs — the priority-2 target, witnessed

The section-open idiom in this module is a **3-dword descriptor `{u32 classId/iid, u32 groupId, u32 index}`** copied by `FUN_10003529` and opened by `FUN_1001f57c(desc, streamL, streamR)`. The **second dword is the save-file section group** — the same role as the `0x206c6e7c`+group pair the task described, but expressed through this descriptor rather than that literal (grep confirms `0x206c6e7c` is **not** in this slice; it lives in `10014676`/`1001206a`/`1001176e`/`100116e9`, a separate idiom).

| function | role | section group (2nd dword) | class/iid (1st dword) | payload |
|---|---|---|---|---|
| **`0x100032ca`** | SAVE | **`0xa0ab89f0`** (was UNNAMED in task list — now witnessed) | `0xe0faadc7` idx 1, then `0x20631788` idx 0 | iterates occupants, calls `FUN_1001e226` (occupant_save) per item |
| **`0x1000beec`** | SAVE | **`0x80ab8ab0`** (NOT in the task's list — a new group) | `0x406b1196` | packed byte tile-grid blob via `FUN_1000c0c9` |
| `0x1000bc49` | LOAD | (reads via `FUN_1001f360`, group is in the stream header) | — | rebuilds occupant grid from byte buffer |

**`0xa0ab89f0` is confirmed** as the building-occupant-collection save section: `FUN_100032ca` opens it and drives the pinned occupant saver `FUN_1001e226`. **`0x80ab8ab0` is a newly discovered group** (the tile-grid section). The other task-listed unnamed groups (`0x2147c2dd`, `0x80f1e6d3`, `0xc0ab8a88`) do **not** appear in this slice.

### Section reader sentinel `0xDEADBEEF` `[CONFIRMED @0x1001f360]`
`FUN_1001f360` (the load-stream ctor referenced across cluster1) reads a GZ-key triple `{type,group,instance}` via `param_1 vt+0x260` and **validates `this+8 == 0xdeadbeef`** as the section sentinel, rewriting it on the retry path. This is the read side that pairs with the `FUN_1001f57c` write side above.

### Two occupant field (de)serialisers, distinct from `0x1001e516`/`0x1001e226`
- **`0x1001d611` = field SAVE**, **`0x1001d478` = field LOAD** — an exact mirror pair over a different vtable-slot set (writer `vt+0x68/+0x78/+0x88`, reader `vt+0x18/+0x28/+0x38`). `FUN_1001d611` first serialises a 3-dword resource key fetched from service **`0x80199683`**. This is a per-occupant record separate from the collection serialiser.

### Message / notify ids `[CONFIRMED]`
- **`0x82684130`** posted by `FUN_1000836b` alongside resource group **`0x42c1ed2d`** and the `%LANDMARK%` string — landmark placement/notify.
- **`0x35d6918`** and **`0x35d6919`** posted by `FUN_1000b6b4` (service class `0x816c8928`, iid `0x6856f7`) — a location-marker pair (create then finalize).
- These extend cluster1's `0x637c0dab` redraw notify.

### Placement / lot-fitting geometry (priority-3 target)
A coherent placement family is now mapped:
- **`0x1000a62a`** — interactive place attempt with audio feedback: play sound **`0xca`** on success, **`0x1e`/`0x20`** on failure (sound service class `0xfa2`).
- **`0x10013c2f`** — instantiates occupant CLSID **`0xffd30c03`** (subtype `0x80f48961`, instance `0x1b91`, the SIMGEOM.md "occupant sibling") at a tile.
- **`0x1001223f`** — flood-expands a connected building's bounding rect from a seed tile (4-direction walk, match test `FUN_100121e1==1`).
- **`0x1001334d` / `0x10012e92`** — 3-layer area+cost: `1001334d` drives three layer handlers via selectors `[0x11]/[0x12]/[0x13]`; `10012e92` is a handler computing `area += base+0x60 * w * h` (the same `w*h*perTile` formula in cluster1's `FUN_10024a04`/`FUN_1001408d`).
- **`0x1001303b`** — region occupancy/cost scan across layers `this+0x44/+0x4c/+0x48` under lock `vt+0x148`.
- **`0x1000fed0`** — grid point-query with multi-tile anchor resolution and viewport clipping (confirms the grid struct `+0x90` lock / `+0x98` value array / `+0x9c` flag array, bit0=occupied, bit1=multi-tile→packed anchor, from cluster1).

### Config / INI plumbing
- **`0x1001c6c2`** locates a named INI section and caches its index at `this+0xc0` (state `this+0xb4`); **`0x10017013`** is the concrete keyed value reader it feeds. Together these are the backing implementation of `FUN_1001c047`/`FUN_1001c33e` from cluster1.
- **`0x1001b6a7`** resolves Windows **`.lnk`** shortcuts via `IShellLink`/`IPersistFile` — used when a game data path is a shortcut.

- **Section groups `0x2147c2dd`, `0x80f1e6d3`, `0xc0ab8a88`**: absent from this slice. They appear only in `100032ca` for the *other* list-member `0xa0ab89f0`; the three unmatched ones need whichever functions build their descriptors (not in the 25 largest).

- **Selector fields `local_28[0x11]/[0x12]/[0x13]` in `FUN_1001334d`**: these index into the layer object at runtime; which concrete layer each maps to is not determinable without the object's construction site.
- **iOS cross-check**: not used. Per `SIMGEOM_PROPERTIES.md` the named iOS `Occupant` symbols are the population/disaster occupant, and struct offsets are proven non-transferable (0/5 for goPowerPlant). No `[iOS-HINT]` applied.
